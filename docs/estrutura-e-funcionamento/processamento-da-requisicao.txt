#

Após a inicialização, a classe `Galastri`, localizado em
`galastri/core/Galastri.php`, é iniciada através do método `run()`.

Esta é a classe com a função de coordenar as etapas necessárias para atender a
requisição dentro de uma ordem específica..


### **Carregamento das definições**

Primeiro, `Config::run()` carrega as definições presentes em `galastri/core/config/definitions/` e `app/config/definitions/` (pasta opcional).

Essas definições descrevem as configurações reconhecidas pelo framework, incluindo seus valores padrão e as regras de validação dos valores recebidos.


### **Identificação da rota**

Em seguida, `Router::run()` carrega `app/config/routes.php` e analisa o caminho da URL.

Durante esse processamento, o Router identifica os nós, o endpoint e os parâmetros da rota, aplica as configurações correspondentes e determina o controller e o método que serão utilizados.

A query string é separada antes da divisão do caminho. Assim, em um endereço como:

```
/clientes/listar?pagina=2
```

O trecho `?pagina=2` não é interpretado como parte do nome do endpoint.


### **Aplicação das configurações**

Com a rota identificada, a classe `Galastri` prossegue nesta ordem:

1. Aplica o fuso horário configurado.
2. Seleciona a classe responsável pelo formato de saída.
3. Verifica se há um redirecionamento obrigatório.
4. Verifica se a rota está marcada como indisponível.
5. Verifica a validade da rota, considerando se a saída exige um controller.
6. Verifica a autenticação, quando exigida.
7. Localiza o controller e os métodos correspondentes.

Essas verificações acontecem antes da execução das operações da aplicação. Um redirecionamento ou uma falha de autenticação, por exemplo, pode encerrar o atendimento sem executar o controller.


---

# **Execução do controller**

Quando há um controller, a classe `Galastri` cria uma instância dele. Essa criação executa o construtor herdado de `galastri\modules\Controller`, que coordena as chamadas aos métodos da aplicação.

A sequência é:

1. Executar o método correspondente ao endpoint.
2. Executar o método específico do verbo HTTP, caso exista uma associação configurada para a requisição.
3. Combinar os arrays retornados pelos métodos.
4. Acrescentar os metadados do projeto, caso a configuração `includeProjectMetadata` esteja habilitada.

O método associado ao verbo HTTP é executado **depois** do método do endpoint. Ele não substitui a execução desse primeiro método.

Os dados reunidos ficam disponíveis para a classe de saída preparar a resposta.


---

# **Preparação da resposta**

Após a execução do controller, o framework chama o método `run()` da classe de saída definida pela rota:

| Classe | Resultado                                            |
| -------- | ------------------------------------------------------ |
| `View`       | Monta a página utilizando os arquivos de interface. |
| `Json`       | Prepara a resposta em JSON.                          |
| `File`       | Prepara a entrega de um arquivo.                     |


A saída `File` também permite atender requisições sem um controller, quando o arquivo é resolvido diretamente pelo mecanismo dessa classe.


---

# **Exemplo: página inicial**

A página que acompanha a instalação permite relacionar essa sequência aos arquivos do projeto.

1. Ao acessar `https://galastri.test`, a requisição entra por `public/index.php` e passa pelo bootstrap. Depois, o Router encontra a configuração da raiz `/` e o endpoint `@main` em `app/config/routes.php`.
2. O processamento utiliza:

   | Parte               | Arquivo ou método |
   | --------------------- | -------------------- |
   | Controller          | `app/controllers/Index.php`                   |
   | Método do endpoint | `Index::main()`                   |
   | Classe de saída    | `galastri\core\output\View`                   |
   | Template            | `app/templates/template.php`                   |
   | View                | `app/views/Index/main.php`                   |
3. O método `main()` do exemplo retorna um array vazio. Ainda assim, a página é montada, pois seu conteúdo está nos arquivos de template e view.
